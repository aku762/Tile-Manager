A JSON-driven static catalog builder. Manage tiles — tracks, products, links, posts, events — in a drag-and-drop admin panel, export JSON, and deploy a pre-rendered site to Cloudflare Pages in one build step. Music-first but domain-agnostic: audio players, track pages, playlists, and Schema.org structured data are opt-in features layered on the same tile pipeline.

## How it works

- **Local preview** — open any page in `site/` via Live Server. `app.js` fetches `tiles.json` and `site.json` at runtime and hydrates whatever comment tags exist in the page. No build step needed.
- **Production build** — `npm run build` processes all `*.html` files in `site/`, substitutes `{{SITE_*}}` tokens, pre-renders content from `tiles.json` and `catalog.json`, and writes everything to `dist/`. The `app.js` script tag is stripped from the output.
- **Deploy** — point Cloudflare Pages at the repo with build command `npm run build` and output directory `dist`.

## Project structure

```
core/               ← build engine — safe to pull upstream updates
  build.js          ← reads site/, writes dist/
  app.js            ← local preview hydration (tiles + site.json tokens)
  admin.js          ← admin panel logic
  admin.css         ← admin panel styles
  admin.html        ← admin panel UI

site/               ← your customizations — never touched by core updates
  index.html        ← template + local preview entry point
  site.json         ← site metadata, schema config, player settings
  tiles.json        ← statuses, sections, and tile data
  catalog.json      ← music catalog — artists, labels, releases, tracks
  playlists.json    ← playlists + jingles for the audio player
  style.css         ← public site styles
  player.js         ← audio player, player bar, SPA routing
  images/
    wide/           ← tile images (1200×630 landscape)
    square/         ← square artwork (512×512, used for lock screen)
    portrait/       ← portrait images (1080×1920)
  templates/
    track.html      ← template for generated track pages
    buy.html        ← template for generated buy pages
    info.html       ← template for generated info/blog pages
  content/
    tracks/         ← optional markdown per track (slug.md)
    buy/            ← optional markdown per buy page (slug.md)

source/             ← original source files (not served, not built)
  wide/             ← run convert-tiles.bat → site/images/wide/
  square/           ← run convert-tiles.bat → site/images/square/
  portrait/         ← run convert-tiles.bat → site/images/portrait/

dist/               ← gitignored build output (generated by npm run build)
```

## Getting started

1. **Clone the repo**
2. Edit `site/site.json` with your site details
3. Open `site/index.html` with [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer) to preview locally
4. Open `core/admin.html` via Live Server to manage content — use **Import JSON** to load your existing JSON files
5. Push to GitHub and connect to Cloudflare Pages

## site.json

### Tokens

Tokens in any `site/*.html` file are substituted at build time and resolved at runtime during local preview.

| Token | Field |
|---|---|
| `{{SITE_TITLE}}` | `title` |
| `{{SITE_DESCRIPTION}}` | `description` |
| `{{SITE_TAGLINE}}` | `tagline` |
| `{{SITE_URL}}` | `url` |
| `{{SITE_LOGO}}` | `logo` |
| `{{SITE_OG}}` | `og` |
| `{{SITE_ICON}}` | `icon` |
| `{{SITE_SHORT_NAME}}` | `shortName` (PWA label; defaults to first word of `title`) |
| `{{SITE_FOOTER}}` | `footer` (supports HTML) |
| `{{SITE_SCHEMA}}` | JSON-LD block generated from schema fields — empty string if `schemaType` is not set |

### Schema fields

| Field | Type | Description |
|---|---|---|
| `schemaType` | string | Schema.org type (e.g. `"MusicGroup"`, `"Person"`, `"Organization"`). Leave empty to disable. |
| `artistName` | string | Schema `name` — separate from `title` so branding and schema identity can differ. |
| `sameAs` | array | External profile URLs for Google's Knowledge Graph (Spotify, MusicBrainz, Wikipedia, etc.) |
| `alternateName` | array | Aliases and stage names — links all variants to the same entity. |
| `genre` | array | Genre tags — helps Google disambiguate the artist entity. |
| `foundingLocation` | string | City/region — serialized as a `Place` object in the schema. |
| `shortName` | string | PWA homescreen icon label (defaults to first word of `title`). |
| `themeColor` | string | Browser chrome tint and PWA manifest color (default `#0d0f12`). |

### Player settings

```json
{
  "player": {
    "autoShow": false
  }
}
```

When `autoShow: true` the player bar appears on load and starts the first track of the default playlist automatically. Default `false`.

## Section tags

HTML comment tags control where content is injected. Place them anywhere in any `site/*.html` file — all are optional and silently skipped if absent.

| Tag | Output |
|---|---|
| `<!--FILTERS-->` | Status filter buttons |
| `<!--SECTIONS-->` | All visible non-featured sections |
| `<!--FEATURED-->` | The featured section (tiles sorted by featured order) |
| `<!--SECTION:ID-->` | One specific section by its ID — renders even if the section is hidden from `<!--SECTIONS-->` |

This lets you build multi-page sites — place different section tags on different HTML files and each page gets exactly the content you want.

## Tile types

Every tile has a `type` field that controls how it renders and which admin fields are shown.

| Type | Behavior | Key fields |
|---|---|---|
| `link` | Default. Tile is an `<a>` to an external URL. Optional `slug` still generates a track page. | `href`, `domain` |
| `catalog` | Tile plays a catalog entry — no inline audio. `href` auto-sets from the catalog entry's page. | `catalogRef` |
| `buy` | Price display tile. Generates a sale page at `buy/<slug>/` from `site/templates/buy.html`. `Product` + `Offer` schema. | `slug`, `price` |
| `info` | Blog/event/content tile. Generates a page at `<slug>/` from `site/templates/info.html`. `Article` schema. | `slug` |

Tiles with no `type` field default to `link` behavior — existing `tiles.json` files are unaffected.

## tiles.json structure

```json
{
  "statuses": [
    { "id": "active", "label": "ACTIVE", "color": "#39ff84" }
  ],
  "sections": [
    { "id": "abc123", "title": "PICKS", "featured": true },
    { "id": "def456", "title": "TRACKS" },
    { "id": "ghi789", "title": "ARCHIVED", "visible": false }
  ],
  "tiles": [
    {
      "id": "1748123456789", "section": "def456",
      "type": "link",
      "cat": "TRANCE", "name": "TILE NAME",
      "desc": "Description text.",
      "status": "active",
      "domain": "example.com",
      "href": "https://example.com",
      "image": "example.webp",
      "showImage": true,
      "featured": 1,
      "audio": "audio/track.mp3",
      "track": "Track Title",
      "artist": "Artist Name",
      "album": "Album Name",
      "slug": "track-title"
    }
  ]
}
```

### Section fields

| Field | Type | Description |
|---|---|---|
| `id` | string | Stable identifier assigned at creation — never changes. Controls nothing; display order is array position. |
| `title` | string | Display name |
| `visible` | boolean | `false` hides the section from the built site; omit or `true` to show |
| `featured` | boolean | Designates this as the one featured section — tiles are sourced by `featured` order number, not section assignment |

### Tile fields

| Field | Type | Description |
|---|---|---|
| `id` | string | Stable identifier assigned at creation (timestamp-based) — never changes on export |
| `section` | string | ID of the section this tile belongs to |
| `type` | string | `link` (default) · `catalog` · `buy` · `info` — controls rendering and admin fields |
| `cat` | string | Category label shown above the tile name |
| `name` | string | Tile display title |
| `desc` | string | Short description |
| `status` | string | ID of a status from the `statuses` array |
| `domain` | string | Domain shown at the bottom of the tile; used for the favicon |
| `href` | string | Link URL |
| `image` | string | Filename in `site/images/wide/` — same name used across all three image folders |
| `showImage` | boolean | `true` renders the image area. Default `false` (compact tile). |
| `expand` | boolean | `true` makes the tile standalone — never stacks, no gradient, fills row height. Default `false`. |
| `visible` | boolean | `false` hides the tile from the built site and local preview |
| `featured` | number | Position in the featured section (1 = first). Omit or `0` to exclude. |
| `catalogRef` | string | Catalog entry slug — used with `type: "catalog"` tiles |
| `slug` | string | URL-safe identifier. For `link` tiles: generates `tracks/<slug>/`. For `buy`: generates `buy/<slug>/`. For `info`: generates `<slug>/`. Also updates the URL to `site.com/#slug` on play. |
| `price` | string | Display price (e.g. `"$24.99"`) — shown on `buy` tiles |
| `audio` | string | Relative path or URL. Renders an inline audio player on the tile. |
| `track` | string | Track title for the OS lock screen card. Defaults to `name`. |
| `artist` | string | Artist name for the lock screen card. |
| `album` | string | Album name for the lock screen card. |

## Tile images

Images live in `site/images/wide/` and are referenced by filename in the tile's `image` field. Use the same filename across all three image folders — the folder determines the format:

| Folder | Size | Used for |
|---|---|---|
| `images/wide/` | 1200×630 | Tile display |
| `images/square/` | 512×512 | Lock screen artwork (tried first, falls back to wide) |
| `images/portrait/` | 9×16 | Portrait tile format (future) |

**Converting source images:** each `source/` subfolder has its own `convert-tiles.bat`. Requires [ImageMagick](https://imagemagick.org/).

| Folder | Converts to | Output size |
|---|---|---|
| `source/wide/` | `site/images/wide/` | 900px wide WebP |
| `source/square/` | `site/images/square/` | 512×512 WebP (center crop) |
| `source/portrait/` | `site/images/portrait/` | 1080×1920 WebP (center crop) |

## Tile layout

By default tiles are compact and eligible for stacking. Two consecutive compact tiles in a section are automatically grouped into one grid cell, splitting the height equally.

| Mode | How | Result |
|---|---|---|
| Compact (default) | `showImage` off, `expand` off | Small tile, stacks with the next compact tile |
| Image / gradient | `showImage` on | Full-height tile with image or gradient placeholder |
| Expand | `expand` on | Full-height standalone tile, no image area — description fills the space |

On mobile (single column) stacking is disabled and all tiles flow normally.

## Audio tiles

Set the `audio` field on any tile to a relative path or URL. The tile renders an inline player: play/pause, scrubber with handle, and timestamp.

- **Compact tile:** player bar sits above the category label
- **Image tile:** slim frosted bar overlaid at the bottom of the image — click the image to play/pause

Only one track plays at a time.

### Persistent player bar

A fixed bar at the bottom of the screen shows the currently playing track — thumbnail, name, artist, play/pause, scrubber, time. It slides up on first play and stays visible while navigating between pages via SPA routing. Clicking the track name or thumbnail navigates to that track's page.

### Lock screen (Media Session API)

On supported browsers, the OS lock screen and Control Center show a full media card with prev/next buttons. Populate `track`, `artist`, `album`, and `image` on the tile for the best experience. Artwork uses `images/square/` if available, falls back to `images/wide/`.

### Hash routing

Set a `slug` on any audio tile and the URL updates to `site.com/#slug` when that track plays. Sharing that URL scrolls to the tile and starts playback automatically.

## Music catalog

`site/catalog.json` is the authoritative source for music data — artists, labels, releases, and tracks. It's entirely separate from `tiles.json` (which controls display). A music site uses both; a non-music site ignores `catalog.json` entirely.

### catalog.json structure

```json
{
  "artists": [
    { "id": "dj-typhoon", "name": "DJ Typhoon" }
  ],
  "labels": [
    { "id": "smart-aleck", "name": "Smart-Aleck Recordings" }
  ],
  "releases": [
    {
      "id": "medusas-escape-ep",
      "title": "Medusa's Escape EP",
      "artist": "DJ Typhoon",
      "label": "Smart-Aleck Recordings",
      "type": "EP",
      "cat": "TRANCE",
      "release_date": "2006-03-15",
      "catalog_number": "SAR-001",
      "image": "medusasescape.webp",
      "desc": "Short description.",
      "tracks": ["medusas-escape"]
    }
  ],
  "tracks": [
    {
      "slug": "medusas-escape",
      "title": "Medusa's Escape (2006 Mix)",
      "artist": "DJ Typhoon",
      "album": "Medusa's Escape EP",
      "bpm": 138,
      "key": "8A / Am",
      "duration": "6:42",
      "cat": "TRANCE",
      "desc": "Short description.",
      "audio": "audio/medusas-escape.mp3",
      "image": "medusasescape.webp",
      "visible": true
    }
  ]
}
```

**`artists`** — reference table. Tracks and releases reference artists by name; the admin enforces consistency via a dropdown. Single-artist sites can skip this and use plain name strings.

**`labels`** — reference table. Labels belong on releases, not individual tracks.

**`releases`** — `type` is `LP`, `EP`, `Single`, `Mix`, or `Compilation`. `tracks` is an ordered slug list. Adding a track to a release auto-sets `track.album` if the track has none.

**`tracks`** — `slug` is the primary key and URL identifier. `audio` absent = catalog-only (shows in catalog, skipped by player). `visible: false` hides the track entirely.

### Build output from catalog

- **Track pages** — `build.js` generates `dist/tracks/<slug>/index.html` for every visible track with an audio file. Schema.org `MusicRecording` with `inAlbum` and `recordLabel` derived from releases (type priority: LP/Album > Compilation > EP > Single > Mix). Duration string (`6:42`) is converted to ISO 8601 (`PT6M42S`) automatically.
- **Catalog script** — `window._catalog`, `window._playlists`, `window._jingles`, and `window._sitePlayer` are injected into every built page for the player.

### playlists.json structure

```json
{
  "default": "main",
  "playlists": [
    {
      "id": "main",
      "title": "Main",
      "tracks": ["medusas-escape", "jingle:end-release", "another-track"]
    }
  ],
  "jingles": [
    { "id": "end-release", "title": "Thanks for listening", "audio": "jingles/end.mp3" }
  ]
}
```

Playlists reference tracks by catalog slug. Jingles (short audio clips — intros, outros, IDs) are embedded directly in `playlists.json` and referenced as `jingle:<id>` entries anywhere in the track list. The player resolves jingles from `window._jingles` and plays them inline in the sequence.

If `playlists.json` is absent, a default playlist is auto-synthesized from all catalog tracks that have audio.

## Track pages

Any tile with a `slug` field generates a static page. Catalog entries generate richer pages with more schema data. The template at `site/templates/track.html` is fully customizable.

**Tokens available in `track.html`:**

| Token | Value |
|---|---|
| `{{TRACK_TITLE}}` | Track title |
| `{{TRACK_CAT}}` | Category tag |
| `{{TRACK_DESC}}` | Description |
| `{{TRACK_IMAGE}}` | Image filename |
| `{{TRACK_SLUG}}` | Slug |
| `{{TRACK_META}}` | `artist · album` |
| `<!--TRACK_HERO-->` | Full-width hero image |
| `<!--TRACK_PLAYER-->` | Inline audio player |
| `{{TRACK_CONTENT}}` | Rendered markdown from `site/content/tracks/<slug>.md` |
| `{{TRACK_SCHEMA}}` | `MusicRecording` JSON-LD block |

## Admin panel

Open `core/admin.html` directly via Live Server. State is saved to `localStorage`. Each data type has its own export button.

The admin has four tabs:

- **Tiles** — add, edit, copy, delete, and drag-to-reorder tiles. Each row has a favicon thumbnail (click to toggle `showImage`), a star (☆/★) to feature/unfeature, and a hide/show toggle.
- **Sections** — add, edit, delete, and drag-to-reorder sections.
- **Statuses** — add, edit, and delete status labels with custom colors.
- **Catalog** — manage all music catalog data with six sub-panels:

| Sub-panel | What it manages | Export |
|---|---|---|
| PLAYLISTS | Playlists and their track order (with jingles) | `playlists.json` |
| JINGLES | Short audio clips referenced in playlists | (part of `playlists.json`) |
| TRACKS | Catalog track entries — slug, title, artist, BPM, key, duration, album, audio, image | `catalog.json` |
| RELEASES | Releases with track lists — title, artist, label, type, date, catalog number | `catalog.json` |
| LABELS | Label reference table | `catalog.json` |
| ARTISTS | Artist reference table | `catalog.json` |

Renaming an artist propagates to all tracks and releases. Renaming a label propagates to all releases. Deleting a jingle removes its `jingle:id` entry from every playlist automatically.

### Playlist editor

Two-panel layout: playlist list on the left, track detail on the right. Drag to reorder tracks. Add tracks from a picker dropdown grouped by TRACKS / JINGLES. Duplicate entries are allowed — useful for repeating jingles. The default playlist (green DEFAULT badge) is what `player.autoShow` and Media Session use.

### Release editor

Same two-panel layout as playlists. Adding a track to a release auto-populates `track.album` from the release title if the track has no album set.

### Tile edit modal

A `TYPE` dropdown at the top shows and hides field groups based on the selected type. `catalog` type replaces all audio fields with a single catalog entry dropdown. `buy` shows a price field. `info` shows only the slug. `link` (default) shows domain, href, image, audio, and media fields.

### Visibility

Both tiles and sections support a `visible` field. Hidden items are excluded from the built site and local preview but remain editable. Hidden rows show an orange left border.

### Featured section

One section carries `"featured": true`. It displays all tiles with a `featured` order number, sorted by that number — section assignment is ignored. Click ☆ in the tile row to feature; drag to reorder within the featured section filter. The featured section cannot be deleted, only hidden or renamed.
